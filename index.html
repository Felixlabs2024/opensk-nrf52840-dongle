三条必须先知道的结论Three things you must know first

① USB DFU 是死路

出厂 bootloader 有厂商签名墙。我们试过补 sd_req 候选表（24 个版本号）、把 fw_version 改成 0xFFFFFFFF、甚至用 Nordic 调试私钥做 210 字节 SignedCommand —— 全部返回 InvalidObject（trace 里 Execute(op 4) 返回 result 5）。

只有 SWD 一条路。

② platform.hex 不能烧

它用 4 条 02（Extended Segment Address）记录把同一段 0x0000–0xFFFF 重叠映射了 4 次。probe-rs 只写对第一段，而 --verify 还会误报通过（它校验的是自己解析出的、自洽但错误的镜像）。

正确做法：烧 target/thumbv7em-none-eabi/release/bootloader 那个 ELF。

③ 真正的拦路虎在 0xE0000

Nordic 原厂 DFU bootloader 挡在 MBR 与应用程序之间，校验不通过就永远停在 Open DFU Bootloader（VID_1915:PID_521F + COM 口），按键/复位/拔插都无效。

解决办法：烧录时加 --allow-erase-all。全片擦除会顺手把它清成空白，MBR 校验失败后仍会跳到 0x1000。

想深挖原理 → docs/02-architecture.md；全部坑 → docs/01-pitfalls-and-fixes.md

① USB DFU is a dead end

The stock bootloader is protected by a vendor signature wall. We tried stuffing the sd_req field with all 24 candidate SoftDevice versions, setting fw_version to 0xFFFFFFFF, and even signing a 210-byte SignedCommand with Nordic's debug key — every attempt returns InvalidObject (Execute(op 4) → result 5 in trace).

SWD is the only path.

② Never flash platform.hex

It encodes addresses with four overlapping 02 (Extended Segment Address) records mapping the same 0x0000–0xFFFF window four times. probe-rs only lands the first segment, and --verify still reports success because it verifies its own (self-consistent but wrong) parse.

Use the ELF at target/thumbv7em-none-eabi/release/bootloader instead.

③ The real blocker sits at 0xE0000

The stock Nordic DFU bootloader sits between the MBR and the application. When its validation fails the device stays in Open DFU Bootloader (VID_1915:PID_521F + a COM port) forever. Buttons, reset, replugging — nothing helps.

Fix: add --allow-erase-all when flashing. The full chip erase blanks it; the MBR then falls through to 0x1000.

烧录：命令与坑Flashing: command & caveats

标准命令

probe-rs download --chip nRF52840_xxAA --probe 1366:0101 \
  --allow-erase-all --binary-format elf --verify --reset \
  firmware/opensk-nrf52840dongle.elf

--probe 1366:0101 只按 VID:PID 选探针；接了多台 J-Link 时写成 1366:0101:<序列号>（用 probe-rs list 查）。

参数作用
--allow-erase-all全片擦除。会顺手清掉 0xE0000 的原厂 bootloader（正是我们要的），也会清掉 store 区（所有凭据）
--binary-format elf显式指定格式。若烧 hex 必须写 hex，否则报 Unknown file magic
--verify写完校验
--reset写完复位
如果设备已开启 APPROTECT：上面的命令会失败（probe-rs 无法 attach）。必须先 ERASEALL 全擦，再烧固件，最后写回 UICR —— 用 ./scripts/recover.sh。

产物选择的坑

文件能不能烧
target/wasefire/platform.hex❌ 不要用（重叠段编码，probe-rs 解析不了）
target/wasefire/platform_a.bin❌ 只有 applet 包
target/wasefire/platform.wfb❌ bundle 容器，不是给 SWD 的
release/bootloader（ELF）✅ 就用这个：.runner 段已注入 applet

The canonical command

probe-rs download --chip nRF52840_xxAA --probe 1366:0101 \
  --allow-erase-all --binary-format elf --verify --reset \
  firmware/opensk-nrf52840dongle.elf

--probe 1366:0101 selects by VID:PID only; with multiple J-Links use 1366:0101:<serial> (see probe-rs list).

FlagEffect
--allow-erase-allFull chip erase. Blanks the stock bootloader at 0xE0000 (what we want) and the store region (all credentials)
--binary-format elfExplicit format. For hex you must pass hex, otherwise Unknown file magic
--verifyVerify after write
--resetReset after write
If APPROTECT is already enabled this command fails (probe-rs cannot attach). You must ERASEALL, flash, then restore UICR — use ./scripts/recover.sh.

Picking the right artifact

FileFlasheable?

target/wasefire/platform_a.bin❌ applet bundle only
target/wasefire/platform.wfb❌ wasefire bundle container

安全：强烈建议开启 APPROTECTSecurity: enable APPROTECT

不开读保护 = 没有保护。任何人拿到这块板子、接 4 根线、跑一条 probe-rs read，就能把整片 flash 导出来 —— 里面有 master key（明文），而所有私钥都是用它加密的。PIN 不加密私钥，只控制使用授权。导出 flash = 全部私钥泄露，连 PIN 都不用破。

一条命令开启

./scripts/protect.sh

它做的是「保留式写入」：读出整页 UICR 备份 → 只把 0x208–0x20B 改成 0 → 整页写回。实测只有这 4 个字节变化，NRFFW[0]、PSELRESET、所有凭据、PIN 全部保留。

能力未保护已保护
SWD 读 flash / store✅ 随便读❌ 硬件切断
改固件植入后门✅❌
重置 PIN 计数器后爆破✅❌（8 次锁死）
ERASEALL 全片擦除✅✅ 但仍可用 —— 擦完什么都没了

代价（必须提前接受）

  • 不能再用 SWD 调试/读回验证；
  • 升级固件必须全擦重刷：./scripts/recover.sh（清空所有凭据，需重新注册）；
  • 不会变砖：ERASEALL 永远可用，最坏就是全擦重来。

开了也挡不住的

  • 故障注入：legacy APPROTECT（build code A/C）可电压毛刺绕过（CVE-2020-27211，成功率 85%+，市价 $500–900）；新版 SECUREAPPROTECT（B0/D0+）需 EMFI，成功率 40–60%，$1200+；
  • 固件漏洞：只挡调试器，不挡"芯片自己跑被利用的代码"；
  • 免按键：偷不走密钥，但能使用它 —— 未强制 UV 的站点连 PIN 都不用。要堵这条得去掉 touch.rs 补丁。

完整威胁模型见 docs/03-security.md。

No read-out protection = no protection. Anyone holding this dongle can wire 4 pins and run one probe-rs read to dump the entire flash — including the plaintext master key that encrypts every private key. PIN does not encrypt private keys; it only gates usage. Dump the flash and you have every key, no PIN needed.

One command

./scripts/protect.sh

It performs a preserve-style write: read and back up the whole UICR page → rewrite only 0x208–0x20B as zero → write the page back. Measured: only those 4 bytes change; NRFFW[0], PSELRESET, all credentials and the PIN survive.

CapabilityUnprotectedProtected
SWD read of flash / store✅ anything❌ hardware-gated
Patch firmware with a backdoor✅❌
Reset PIN counter then brute force✅❌ (locks after 8)
ERASEALL✅✅ still possible — but it destroys everything

Cost

  • No more SWD debugging or read-back verification;
  • Firmware upgrades require a full erase: ./scripts/recover.sh (wipes all credentials);
  • Cannot brick: ERASEALL always works — worst case is start over.

What it does not stop

  • Fault injection: legacy APPROTECT (build code A/C) falls to voltage glitching (CVE-2020-27211, 85%+, $500–900); SECUREAPPROTECT (B0/D0+) needs EMFI, 40–60%, $1200+;
  • Firmware bugs: it blocks debuggers, not exploited code running on-chip;
  • No-touch patch: keys can't be stolen but the device can be used — sites without mandatory UV don't even ask for a PIN. Remove the touch.rs patch if that matters.
